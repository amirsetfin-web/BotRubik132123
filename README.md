# بات پشتیبانی روبیکا — نسخه نهایی

## 📁 فایل‌ها
| فایل | کار |
|---|---|
| `config.py` | تنظیمات، سیستم رنک (HELPER/MOD/ADMIN/MANAGER/OWNER)، وضعیت‌های تیکت |
| `database.py` | همه‌ی کار با دیتابیس SQLite (تیکت، پیام، Staff، FAQ، یادداشت داخلی) |
| `keyboards.py` | تمام کیبورد/دکمه‌های شیشه‌ای |
| `bot.py` | منطق اصلی بات (روتر پیام‌ها، پنل Staff، FSM) |

---

## ✅ قابلیت‌های نهایی (خلاصه)
- **ورود اولیه:** قبل از نمایش منو، از کاربر نام Minecraft می‌پرسه و همون رو به‌عنوان نام نمایشی در همه‌جا (تیکت، اطلاعات کاربر، اعلان‌ها) استفاده می‌کنه.
- **تیکت:** ساخت با شماره‌ی سراسری، جلوگیری از تیکت تکراری (تا وقتی یکی باز باشه)، گفتگوی پیوسته (بدون نیاز به کلیک تکراری روی «پاسخ»).
- **پیام‌رسانی هوشمند:** تا وقتی تیکتی Claim نشده فقط یک اعلان اولیه به همه‌ی Staffها می‌ره (نه اسپم هر پیام)؛ به محض Claim شدن، فقط همون Staff پیام‌ها رو می‌گیره.
- **بستن تیکت:**
  - کاربر: باید تأیید کنه («مطمئنی؟» ✅/❌)، نیازی به دلیل نداره.
  - Staff: باید حتماً یک دلیل/موضوع برای بستن بنویسه.
  - در هر دو حالت، یک پیام کامل (شماره تیکت، بسته‌شده توسط کی، دلیل، زمان) برای **همه‌ی Staffها** ارسال می‌شه.
  - بعد از ثبت امتیاز/نظر کاربر، یک پیام تکمیلی هم برای همه‌ی Staffها می‌ره.
- **رنک‌بندی Staff:** 🧰 هلپر < 🛡️ ماد < ⚙️ ادمین < 📋 منیجر < 👑 اونر — هرکدوم دسترسی‌های خودشون رو دارن (`config.PERMISSION`).
- **پنل کامل Staff:** فیلتر تیکت‌ها با شمارنده، تیکت‌های من، آمار من/سیستم، بدون‌پاسخ، معطل، جستجو، یادداشت داخلی روی تیکت (فقط Staffها می‌بینن)، Claim با قفل اتمیک (بدون Race Condition)، انتقال تیکت، مدیریت Staff (افزودن با آیدی، تغییر رنک با دکمه، حذف، لیست)، اعلان همگانی (به همه‌ی Staffها یا همه‌ی کاربرانی که با بات شروع کردن).

## 🚀 نصب و اجرا
```bash
pip install rubpy
python bot.py
```
بار اول با اسکن QR از اکانت روبیکا لاگین می‌کنید. `config.py` رو باز کنید و `INITIAL_OWNER_IDS` رو با آیدی خودتون (همون که به‌عنوان بالاترین دسترسی Owner می‌خواید باشه) پر کنید.

## 🔗 چطور به گیت‌هاب وصلش کنم؟

### حالت ۱: قبلاً یک ریپازیتوری روی گیت‌هاب دارید
```bash
# 1) این پوشه رو کلون کنید (یا از قبل دارید)
git clone https://github.com/USERNAME/REPO_NAME.git
cd REPO_NAME

# 2) این ۴ فایل رو داخل پوشه‌ی پروژه کپی/جایگزین کنید
#    (config.py, database.py, keyboards.py, bot.py)

# 3) تغییرات رو اضافه و کامیت کنید
git add .
git commit -m "افزودن سیستم رنک، بستن هوشمند تیکت و پنل کامل Staff"

# 4) پوش به گیت‌هاب
git push origin main
```
اگه نام برنچتون `master` هست به‌جای `main` همون رو بنویسید.

### حالت ۲: هنوز ریپازیتوری نساختید
```bash
# 1) داخل پوشه‌ی پروژه (همونجایی که فایل‌های bot.py و... هستن)
git init
git add .
git commit -m "نسخه اول بات پشتیبانی روبیکا"

# 2) یک ریپازیتوری خالی توی گیت‌هاب بسازید (از سایت github.com -> New repository)
#    بدون اضافه کردن README/گیت‌ایگنور در همون لحظه، تا تداخل نداشته باشه

# 3) ریموتش رو وصل کنید و پوش کنید
git remote add origin https://github.com/USERNAME/REPO_NAME.git
git branch -M main
git push -u origin main
```

### نکته‌ی مهم امنیتی
`support_bot.db` (فایل دیتابیس) و هر فایل session که rubpy در لاگین QR می‌سازه (معمولاً `support_bot.session` یا مشابه) **نباید** روی گیت‌هاب پابلیک آپلود بشه، چون شامل اطلاعات تیکت‌های کاربران و نشست لاگین اکانت روبیکاست. یک فایل `.gitignore` با این محتوا بسازید:
```
*.db
*.session
__pycache__/
*.pyc
```

## ⚙️ نحوه کار بات (خلاصه معماری)
1. **`bot.py`** با استفاده از `rubpy.Client` به روبیکا وصل می‌شه و منتظر پیام (`@app.on_message`) و کلیک روی دکمه‌های شیشه‌ای (`@app.on_callback_query`) می‌مونه.
2. هر کاربر (چه عادی چه Staff) یک ردیف در جدول `user_state` داره که وضعیت فعلی گفتگو (مثلاً «منتظر نام ماینکرفتی»، «داخل چت تیکت #۵») و context مربوطه (JSON) رو نگه می‌داره — این همون FSM (ماشین‌حالت) ساده‌ایه که تشخیص می‌ده پیام بعدی کاربر باید کجا بره.
3. جدول `staff` رنک هر Staff رو نگه می‌داره؛ `has_rank()` چک می‌کنه آیا رنک کافی برای یک عملیات خاص وجود داره یا نه (بر اساس `config.PERMISSION`).
4. جدول `tickets` مرکز اصلی داده‌هاست: شماره‌ی سراسری (AUTOINCREMENT)، وضعیت (NEW/IN_PROGRESS/...)، Staff مسئول، دلیل، دلیل بستن، امتیاز، نظر.
5. **قفل Staff:** وقتی یک Staff تیکتی رو Claim می‌کنه، یک تراکنش اتمیک (`BEGIN IMMEDIATE`) در SQLite چک می‌کنه که هم‌زمان یک نفر دیگه اون تیکت رو نگرفته باشه؛ تا وقتی این تیکت باز نشده، همون Staff نمی‌تونه تیکت جدید Claim کنه.
6. تمام رویدادها (ساخت، پاسخ، بسته‌شدن، انتقال، Claim) در جدول `ticket_activity` لاگ می‌شن تا تاریخچه‌ی کامل هر تیکت قابل‌مشاهده باشه.

## ⚠️ قبل از دیپلوی روی VPS حتماً این‌ها رو تست کنید
چون در محیط من نه اکانت روبیکا بود نه دسترسی شبکه، امکان اجرای واقعی بات رو نداشتم. این موارد رو با دقت با نسخه‌ی نصب‌شده‌ی `rubpy`ـتون تطبیق بدید (داخل کد هم با `TODO/VERIFY` علامت زدم):

1. **اسم دقیق دکوراتور کلیک روی دکمه‌های شیشه‌ای** (`@app.on_callback_query`) و اینکه `button_id` دقیقاً از کجای آبجکت `update` خونده می‌شه.
2. **تشخیص "اولین ورود" کاربر:** فعلاً با چک‌کردن نبودن رکورد کاربر در دیتابیس تشخیص داده می‌شه؛ اگه rubpy نوع Update مشخصی برای دکمه‌ی Start بومی روبیکا داره (که معمولاً باید داشته باشه)، بهتره مستقیم از همون استفاده کنید تا دقیق‌تر باشه.
3. مسیر کامل «ساخت تیکت → Claim → گفتگو → بستن → امتیاز → نظر → اعلان به همه‌ی Staffها» رو دستی امتحان کنید.
4. سناریوی هم‌زمانی: با دو اکانت Staff واقعی امتحان کنید که آیا قفل Claim درست کار می‌کنه یا نه.

هر کدوم از این‌ها باگ داشت، دقیقاً چی رو امتحان کردید و چه اتفاقی افتاد رو بگید تا فیکسش کنم.
